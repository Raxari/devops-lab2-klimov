## Сборка и запуск

Требуется работающий Docker Engine. Выполнять в каталоге проекта:

```sh
docker build --build-arg VERSION=1.0 -t klimov-01/probe:0.9 .
docker run -d --name klimov-01-lr2-web -p 8003:5001 klimov-01/probe:0.9
curl -s http://localhost:8003/me
curl -s http://localhost:8003/uptime
```

Имя klimov-01-lr2-web позволяет сохранить одноимённые контейнеры других работ. Порт 8003 должен быть свободен.

## Ответы приложения

- `/`: строка с маркером и именем контейнера.
- `/me`: student, group, marker, hostname, version.
- `/uptime`: marker и uptime_seconds — секунды работы процесса с округлением до одного десятичного знака.

Базовый образ варианта — python:3.12-alpine. APP_PORT=5001 и MARKER=sitelab задаются через ENV. При запуске MARKER можно изменить ключом -e. ARG VERSION записывается при сборке в /app/VERSION; ключ -e VERSION=999 не изменяет файл.

Dockerfile сначала копирует requirements.txt, затем устанавливает зависимости и копирует код. .dockerignore исключает учебный dump.sql, кеш Python и .git. Dockerfile.slim нужен только для дополнительного опыта переносимости; основным остаётся Dockerfile на Alpine.

## Учебный опыт с PostgreSQL

Образ базы: postgres:16-alpine, опубликованный порт: 8005, внутренний: 5432. Каталог /var/lib/postgresql/data подключается к именованному тому. Учебные параметры: POSTGRES_PASSWORD=lab, POSTGRES_DB=lab. Таблица marks(who VARCHAR(64)) содержит строку `klimov-01 sitelab`. Это отдельный опыт с томом: само приложение probe из лабораторной 2 к базе не подключается.

## Уборка приложения

```sh
docker rm -f klimov-01-lr2-web
docker image rm klimov-01/probe:0.9
```

Не удаляйте тома и контейнеры других лабораторных работ.
